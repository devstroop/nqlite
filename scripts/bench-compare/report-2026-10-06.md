# Cross-DB benchmark — with the recall column (2026-10-06)

Host: Intel Xeon E5-2640 v4 @ 2.40 GHz, 64 GB, Linux — **not the Raspberry Pi
of the 2026-08-04 report; never compare numbers across these two reports.**
Python 3.10.12, sqlite-vec **0.1.9**, sqlite 3.37.2; lancedb / chromadb not
installed (honest skip). Commit `c5f1fb8`, release-profile nql binaries.

Corpus: 1000 and 5000 rows, dim-8 float vectors, 8-word vocabulary, xorshift64*
seed 42 (byte-identical to `nql-bench`). kNN = 50 queries, k = 10. All times in
milliseconds; lower is better. Only same-shape cells compare. **`rec@10` is new
in this report** (the 2026-08-04 table predates the quality column).

## The recall column (this run's addition)

Two different bases, stated plainly (topic-9 L2/L4 rules):

- **nqlite** `rec@10` = HNSW recall@10 vs exact brute-force on its **own
  dim-64 set**, 20-query mean (`nql-bench --recall --features hnsw`,
  `exact_recall_at_10 = 1.0` pins the ground truth). 1.0000 @1k, **0.9600
  @5k** — the #96 gate's degradation curve, showing up in a cross-DB table
  for the first time.
- **sqlite-vec** `rec@10` = mean over **30 queries vs EXACT cosine top-10 on
  this shared dim-8 corpus** (the #96 method, competitor-sized set). vec0
  0.1.9 is L2-only, so vectors are **unit-normalized at insert** (for unit
  vectors L2 ranking ≡ cosine ranking) — documented in the driver. 1.0000 at
  both sizes: vec0 is exact at this scale, so the number pins *implementation
  correctness*, not an ANN trade-off.

## How to read this (honest)

- **knn** — sqlite-vec (0.15 ms/query @1k) beats nqlite (15.8 ms/query) on
  this axis for two structural reasons: (1) it holds a **persistent index**
  while nqlite rebuilds its index **per query by design** (the result must be
  a pure function of `(store, select)` — determinism is the trade), and (2)
  it stores vectors only — no records, graph, lexical or hybrid operators,
  no transactions. The 2026-08-04 report made the same observation from a
  different machine.
- **bm25 / hybrid** — n/a for competitors; nqlite is the only store here with
  lexical + vector + fusion in one deterministic query.
- **ingest** — nqlite leads sqlite-vec at 1k (13.96 vs 66.92 ms) and the gap
  narrows at 5k (69.81 vs 299.33 ms); both are far above real-time needs.

## What this means (honest)

- The **quality column now exists for both systems** (the R6 remainder):
  nqlite's HNSW is within the gate at 5k and vec0 is exact at this size —
  neither store is returning wrong neighbors on this corpus.
- nqlite's kNN latency gap is the price of per-query index rebuild +
  determinism; the knob remains HNSW tuning (#96's sweep flags), and the
  honest claim stays "only embedded store with records + graph + vectors +
  lexical + hybrid under one deterministic transaction".
- **lancedb/chroma are skipped, not beaten** — the harness prints the skip
  reason; install the drivers to fill those rows.
