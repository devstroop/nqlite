# Cross-DB benchmark — full matrix with the recall column (2026-10-06)

Host: Intel Xeon E5-2640 v4 @ 2.40 GHz, 64 GB, Linux — **not the Raspberry Pi
of the 2026-08-04 report; never compare numbers across these two reports.**
Python 3.10.12; drivers: sqlite-vec **0.1.9**, lancedb **0.39.0**,
chromadb **1.5.9** (sqlite 3.37.2). Commit `c5f1fb8` + this branch;
release-profile NQL binaries. `ANONYMIZED_TELEMETRY=False` for chroma.

Corpus: 1000 and 5000 rows, dim-8 float vectors, 8-word vocabulary, xorshift64*
seed 42 (byte-identical to `nql-bench`). kNN = 50 queries, k = 10. All times in
milliseconds; lower is better. Only same-shape cells compare. **`rec@10` now
covers every system** (the 2026-08-04 table predates it; its sqlite-vec row
predates the driver's first successful execution).

## The recall column (every system, one method per basis)

- **nqlite** `rec@10` = HNSW recall@10 vs exact brute-force on its **own
  dim-64 set**, mean over its recall run (`nql-bench --recall --features hnsw`,
  `exact_recall_at_10 = 1.0` pins ground truth). 1.0000 @1k, **0.9600 @5k** —
  the #96 gate's degradation curve, in a cross-DB table for the first time.
- **competitors** `rec@10` = mean over **30 queries vs EXACT cosine top-10 on
  this shared dim-8 corpus** (the #96 method, competitor-sized set). All three
  default to L2, so vectors are **unit-normalized at insert** (for unit vectors
  L2 ranking ≡ cosine ranking) — one shared `unit`/`mean_recall10` helper in the
  driver; lancedb rows gained an `id` column for the index mapping. **1.0000 at
  both sizes for all three**: they are exact at this scale, so the numbers pin
  *implementation correctness* rather than an ANN trade-off (that trade-off
  only shows in nqlite's HNSW column).

## How to read this (honest)

- **knn** — indexed stores stay flat while nqlite grows: sqlite-vec
  7.95→13.51 ms and chroma 90.89→92.79 ms across 5× rows; lancedb sits at a
  constant ~300–340 ms (search overhead dominates at this size); nqlite
  795.94→2990.57 ms because it (a) scans exactly and (b) **rebuilds its index
  per query by design** — the result must be a pure function of
  `(store, select)` (determinism is the trade). None of the competitors offer
  records + graph + lexical + hybrid in one query.
- **bm25 / hybrid** — n/a for all three competitors; nqlite is the only store
  here with lexical + vector + fusion in one deterministic query.
- **ingest** — nqlite and lancedb lead (13.04 / 13.39 ms @1k); chroma is an
  order of magnitude slower (428 ms @1k, 2.06 s @5k — per-batch IPC).

## What this means (honest)

- **The quality column exists for every system** (the R6 remainder): no store
  returns wrong neighbors on this corpus; nqlite's 0.96 @5k is the only
  sub-1.0 value and it is ANN-by-choice (gate pinned at 5k, sweep flags exist
  for the 50k regime).
- nqlite's kNN latency gap is structural (exact scan + per-query rebuild);
  the honest claim stays "only embedded store with records + graph + vectors +
  lexical + hybrid under one deterministic transaction".
